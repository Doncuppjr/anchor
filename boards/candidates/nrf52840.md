# nRF52840 platform candidates and current native target

The Pro Micro nRF52840 now has an experimental native NCS 3.3.0 / Zephyr ANCHOR application. Other nRF52840 boards remain candidates for additional board definitions and validation. The current native implementation is documented in [platforms/nordic-nrf52840](../../platforms/nordic-nrf52840/), and the Adafruit bootloader investigation is in [Nordic nRF52840 and Adafruit bootloader investigation](../../docs/NORDIC-NRF52840-BOOTLOADER.md).
Do not create a fake `boards/*.mk` target using Arduino ESP32 libraries. Anchor
currently uses ESP32 `BLE.h`, `Preferences`, Wi-Fi, `WebServer`, `Update`,
ESP-IDF sleep and OTA calls. Shared FrSky parser and application logic can be
ported to an abstract UART / BLE / persistence / power / updater interface.

| Candidate | Memory | BLE | Wi-Fi OTA | Porting status |
| --- | --- | --- | --- | --- |
| Pro Micro nRF52840 | 1 MB internal flash, 256 KB RAM | Yes | No Wi-Fi | Native NCS 3.3.0 build target; bench application, not release-qualified |
| Seeed XIAO nRF52840 / Sense | 1 MB internal flash, 256 KB RAM; 2 MB onboard external flash | Yes | No Wi-Fi | Requires Nordic implementation |
| Seeed XIAO nRF52840 Plus | Same MCU, more GPIO | Yes | No Wi-Fi | Requires Nordic implementation |
| Arduino Nano 33 BLE / Sense | 1 MB flash, 256 KB RAM | Yes | No Wi-Fi | Requires Nordic implementation |
| Adafruit Feather nRF52840 Express | 1 MB flash, 256 KB RAM | Yes | No Wi-Fi | Requires Nordic implementation |
| Generic nRF52840 module/dongle | Depends on board, typically same MCU memory | Yes | No Wi-Fi | Requires Nordic implementation |

The current Pro Micro target uses UARTE0 TX P0.09 / RX P0.10 at 115200 baud,
with USB CDC ACM as a separate console. The custom Adafruit bootloader also
uses GPIO 9/10 for its optional UART DFU path. See the platform build record
for the exact configuration and remaining AT/role/DFU regression items.

Yacht already has an nRF52840/TinyGo implementation, which may provide useful
transport and BLE design references, but do not mix Yacht's sensor/head-tracker
role with Anchor's UART-to-BLE bridge role. Ensure the chosen Nordic board exposes the required application UART and a
reliable way to request bootloader entry. The experimental ANCHOR bootloader
UART path uses GPIO 9/10 at 115200 baud with no hardware flow control on its
current board definition; do not assume those pins map to another carrier. A
stock Nordic DFU bootloader is **not** Espressif ROM download mode. EdgeTX USB
serial passthrough needs chip-specific upload tooling and reliable bootloader
entry. Replace Wi-Fi OTA with Nordic DFU (or another documented mechanism)
and preserve the independent USB UF2 recovery path. Automatic power-loss
rollback has not been demonstrated.

References: Seeed XIAO nRF52840 documentation, Arduino Nano 33 BLE official
product page, Nordic nRF52840 product specifications.
